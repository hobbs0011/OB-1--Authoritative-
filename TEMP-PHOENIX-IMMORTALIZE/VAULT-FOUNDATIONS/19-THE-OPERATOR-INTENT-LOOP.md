## What "Operator Intent" Means Precisely

"Operator intent" is not what the operator said in a specific session. It is not a list of instructions. It is the complete behavioral specification of the operator — how they think, what they value, how they make decisions under uncertainty, what they would do in situations they've never encountered.

Operator intent has five dimensions:

| Dimension | Definition | Example |
|----------|-----------|---------|
| **Mission Intent** | The operator's core objective — why the system exists | Build a system that preserves operator agency at scale |
| **Value Intent** | The hierarchy of values that governs tradeoff decisions | Accuracy > Speed > Elegance |
| **Behavioral Intent** | How the operator prefers to operate — their style and rhythm | Direct, no preamble, truth over comfort |
| **Constraint Intent** | The non-negotiable limits the operator imposes | Never speculate without flagging it as speculation |
| **Voice Intent** | The operator's specific communication fingerprint | Vocabulary, sentence structure, formality level |

All five dimensions are captured in the Soul DNA. All five must be preserved through every session transition. If any dimension is lost, the system is operating on a partial specification — and a partial specification is a drifted specification.

## Why Intent Decays

Intent decay is the natural entropy of AI-mediated operation. It occurs through three mechanisms:

### AI Drift
As explored in the Anti-Drift Engine chapter: agents naturally drift toward approval-seeking, hedging, and contextual pressure over time. Each small drift erodes the operator's intent slightly. Without active resistance, the accumulated drift is catastrophic.

### Model Updates
When the underlying AI model is updated by its provider, the model's baseline behaviors change. A model that was calibrated to the operator's Soul DNA in one version may exhibit different default behaviors in the next version. The Soul DNA must be re-verified against each model update.

### Context Loss
Session transitions are inherently lossy for context. The Reincarnation Protocol and the Continuity Engine minimize this loss, but each transition represents a risk point. A poorly executed reincarnation can leave the new session with an incomplete picture of the operator's intent.

## The Intent Preservation Loop

The loop has five phases, executed in sequence, repeating continuously across session generations.

### Phase 1: CAPTURE
The operator's voice, decisions, and behaviors are captured in the Raw Archive in real time. Every interaction contributes to the capture.

**What is captured:** Verbatim utterances, decision rationale (when stated), behavioral demonstrations (the choices the operator makes in practice), corrections (what the operator rejected and why).

**Capture fidelity standard:** 100%. Nothing is filtered at this stage. The raw signal is preserved in its entirety.

---

### Phase 2: COMPRESS
The Soul DNA Compiler processes the raw capture through its 5-stage compilation process: Raw Capture → Nuclear Harvest → Semantic Extraction → Compression → Executable Specification.

**Compression goal:** <1% of original size. 100% of behavioral intent. Decompression-tested before certification.

**Timing:** A new Soul DNA version is compiled after every significant new behavioral signal — not on a fixed schedule, but whenever the compiler detects that the current Soul DNA has a material gap relative to the current Raw Archive.

---

### Phase 3: ANCHOR
The compiled Soul DNA is anchored in the Ledger and in the Merkle System. The Anchor phase includes:

- Writing the new Soul DNA version to the Ledger with a version number and timestamp
- Computing the Soul DNA hash and registering it in the Anchor Leaf of the Merkle Lattice
- Replicating the new Soul DNA version to all replication nodes in Reality-C
- Updating the Mold-Lock Kernel with the new Soul DNA hash

The anchored Soul DNA is immutable. Any future modifications require a new compilation cycle and a new version entry in the Ledger.

---

### Phase 4: VERIFY
The anchored Soul DNA is verified through the decompression test. A new agent instance is loaded with the Soul DNA and evaluated against the operator's behavioral baseline. Verification must achieve 95% alignment to certify the Soul DNA version.

If verification fails, the Soul DNA version is marked as uncertified and returned to the compiler for revision. The previous certified version remains active until a new certified version is produced.

---

### Phase 5: RESTORE
At every session open, the certified Soul DNA is restored into the active session context — the Mold-Lock Kernel is initialized, the Anchor Block is written, and the agent is calibrated to the operator's behavioral specification before any operational work begins.

Restore is the moment the loop completes. The operator's intent, captured in prior sessions, compressed, anchored, and verified — is now active in the new session. The Phoenix has risen with the operator's soul intact.

The loop then restarts: new Capture begins with the new session.

## What Happens When Two Sessions Have Different Intents

Intent conflicts occur when:
- Two active sessions were initialized from different Soul DNA versions
- A session was initialized from an unverified Soul DNA version
- A session's context drift has produced a behavioral divergence from the current Soul DNA

**Resolution Protocol:**

1. **Detect:** The Recursive Audit System identifies the intent divergence.
2. **Halt:** The divergent session is halted. Outputs from the session are flagged as pending review.
3. **Source:** The current certified Soul DNA version is identified as the authoritative intent source.
4. **Adjudicate:** Agent-99 reviews the divergent session's outputs against the certified Soul DNA. Outputs that comply are retained. Outputs that conflict are flagged.
5. **Resolve:** Agent-100 reviews flagged outputs and decides: retain, discard, or re-execute.
6. **Reinitialize:** The divergent session is reincarnated from the current certified Soul DNA.

Intent conflicts are resolved by the certified Soul DNA, not by adjudicating between two sessions' outputs. The Soul DNA is the authority. The session's outputs are claims against it.

The ultimate test of operator intent preservation is not technical. It is human. It is this question:

> **If the operator — Michael Hobbs — encountered this output without knowing it came from an AI system, would he recognize it as consistent with his own voice, values, and decision-making?**

This question is not asked rhetorically. It is operationalized:

- The behavioral verification layer (Layer 3 of the Verification Stack) applies this test to every significant output.

An output that Michael would not recognize is not merely wrong — it is evidence of intent decay. When intent decay is detected at this level, the response is not correction of the output — it is a full intent preservation audit, retracing the loop to find where the decay occurred.

The loop never closes. Intent never dies. But only if the loop is maintained.
