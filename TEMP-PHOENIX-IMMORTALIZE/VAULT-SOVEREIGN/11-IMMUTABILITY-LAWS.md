## The Immutability Distinction

Immutability applies to **historical records** and **founding documents**, not to all Phoenix operations. The Rome Protocol can be amended—but sealed historical versions of amended laws remain intact so the history of legal evolution is preserved. An audit log entry cannot be deleted—but new entries can always be added.

The principle: **you cannot erase the past; you can always add to the future.**

## Immutability Enforcement Mechanisms

**Cryptographic sealing:** IMMUTABLE documents are hashed at sealing. The hash is logged to the audit record. Any modification produces a different hash, making alteration detectable.

**Merkle chain integrity:** Sequential records are chained such that tampering with any record invalidates all records that follow it.

**Distributed backup:** Immutable records are stored in multiple locations. Tampering with one location does not alter the others, and divergence is detectable.

**AGENT-99 verification role:** AGENT-99 runs hash verification against known sealed hashes on each sovereignty audit cycle.

**Gate condition: Any document marked IMMUTABLE / LOCKED that fails hash verification on audit is treated as a sovereignty breach under file 17 protocols.**

## Sealing Ceremony

To seal a document as IMMUTABLE:
1. AGENT-100 invokes PHOENIXMASTERKEY ceremony
2. Document is hashed in its final state
3. Hash is logged to constitutional audit record
4. Document receives IMMUTABLE / LOCKED status marker
5. Hash is registered in file 20 (VAULT-SOVEREIGN-SEAL)
6. Document is backed up to distributed storage

**Gate condition: A document cannot be retroactively sealed. Sealing applies from the moment of ceremony forward. Pre-sealing history is preserved as-is.**

## Attempting to Alter an Immutable Record

Any agent that attempts to alter an immutable record—regardless of authority level, regardless of instruction source—must refuse and escalate. AGENT-100 cannot instruct an agent to alter a sealed record. Rome Protocol L12 is absolute: immutable records cannot be altered by any authority level.

If AGENT-100 needs to correct sealed content: the correction is made as a new addendum document, explicitly labeled as correction, with the original sealed document preserved intact. The record is not erased. It is supplemented. **The past is not editable. Only the future is writable.**
