────────────────────────────────────────────

REQUIREMENTS:

✓ Understand 60%+ already (comprehensible input)
✓ English subtitles ONLY (if needed)
✓ NO PAUSING for translation

[15 MINUTES] SPEAKING (25% of daily practice)
────────────────────────────────────────────

STRUCTURE:
Minutes 1-5: SHADOWING
• Choose 30-60 second clip from today's listening
• Play and speak along simultaneously
• Match pronunciation, intonation, rhythm
• Repeat 3-5 times until natural

Minutes 6-10: SELF-TALK
• Describe your day in English (out loud)
• Narrate what you're doing
• Express your thoughts and feelings
• No script, spontaneous speaking

Minutes 11-15: RECORD & REVIEW
• Record yourself speaking (1-2 minutes)
• Listen back critically
• Identify areas for improvement
• Note pronunciation challenges

SPECIAL PROTOCOLS:

FOR NHAN (Volume priority):
• Extra 5 minutes: Volume exercises
• Speak at 150% normal volume
• Practice projection from diaphragm
• Record and measure progress

FOR LINH (Pronunciation priority):
• Extra 10 minutes: Targeted sound drills
• Focus on problem sounds (R/L, TH, etc.)
• Minimal pairs practice
• Native comparison recordings

────────────────────────────────────────────

Teach students HOW TO THINK, not just WHAT to memorize

1. PRESENT THE PROBLEM

   Example: "Maybe they just need more grammar study..."

3. PRESENT THE SOLUTION
   Example: "Actually, they need LESS grammar and MORE speaking practice."

4. WRAP IN NARRATIVE (Storytelling)

• Use conversational phrasing
• Good: "So what are the benefits of this approach?"
• Bad: "Benefits:" (flat bullet point heading)
• Engage curiosity first
• Challenge assumptions
• Guide to discovery
• Connect emotionally

7.7 SECURITY LAWS (Technical Gospel 444)
────────────────────────────────────────────

LAW 1: NO INLINE EVENTS (XSS Prevention)
────────────────────────────────────────────

✅ CORRECT:
```javascript
button.addEventListener('click', handleClick);
```

❌ WRONG:
```html
<button onclick="handleClick()">
```

REASON: Inline events are XSS vulnerabilities and violate Content Security Policy


LAW 2: NO UNSAFE HTML (Injection Prevention)
────────────────────────────────────────────

✅ CORRECT:
```javascript
element.textContent = userInput;
```

❌ WRONG:
```javascript
element.innerHTML = userInput;
```

REASON: innerHTML can execute malicious scripts from user input


LAW 3: NO GLOBAL MUTATION OUT OF ENGINE
────────────────────────────────────────────

• All state changes through engine methods ONLY
• No direct window/document modification
• Controlled mutation points
• Predictable state management

REASON: Prevents state corruption and debugging nightmares


LAW 4: ALL STORAGE ENCRYPTED
────────────────────────────────────────────

• Use hashState_SHA256 for integrity verification
• Never store sensitive data in plain text
• Validate data on retrieval
• Implement tampering detection

REASON: Security and data integrity


LAW 5: ALL ADMIN ACTIONS SIGNED
────────────────────────────────────────────

• Authentication required (JWT/HMAC)
• Audit trail mandatory
• Logged with timestamp and user ID
• Multi-factor for critical operations

REASON: Accountability and security audit trail


LAW 6: DOM SANITIZED
────────────────────────────────────────────

• All user input MUST be sanitized
• Use DOMPurify or equivalent
• No trust of external data
• Whitelist approach for allowed tags/attributes

REASON: XSS and injection attack prevention


LAW 7: STATE VECTOR UNIFIED
────────────────────────────────────────────

• Single source of truth for all state
• Immutable state updates (no direct mutation)
• Predictable state transitions
• Event-driven state changes only

REASON: Consistency, predictability, debuggability
