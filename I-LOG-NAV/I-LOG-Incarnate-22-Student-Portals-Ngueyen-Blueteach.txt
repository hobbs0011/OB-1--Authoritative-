## Mission
Consolidate all student portal implementations (OKTAVA, CASA, Nguyen Family, Bluetech) under a single unified prototype. Scout all existing portal artifacts, identify common patterns, and build one reusable portal framework that can serve all contexts via theme/config switching.

## Work Log

### 1. Scouting Phase
Scouted all portal-related directories:

- `public/casa-login/` — CASA English student portal (login + dashboard)
- `public/casa-parent-portal/` — CASA parent portal
- `public/nguyen-login/` — Nguyen family login

### 2. Pattern Analysis
Common patterns across all portals:
- **Login:** Password/PIN-based, role-switching (student/parent/teacher/admin)
- **Dashboard:** Topbar, welcome banner, task list, daily log, progress bars
- **Task API:** `/api/tasks/current`, `/api/tasks/log`
- **Practice API:** `/api/practice`
- **Styling:** Dark theme, purple/gold gradients, card-based layout
- **Differences:** Color schemes, fonts, branding, language (vi/en)

### 3. Prototype Structure
Created unified prototype at `public/student-portal/`:
- `index.html` — Unified login router (portal=query param selects brand)
- `app.html` — Unified portal dashboard
- `assets/css/theme.css` — Theme system (casa, oktava, bluetech, nguyen)
- `assets/css/site.css` — Shared component styles
- `assets/js/app.js` — Unified portal logic (theme, branding, tasks, logs, progress)

### 4. Theme System
Four themes defined in CSS custom properties:
- `casa` — Purple/gold, Orbitron/Rajdhani, CASA English branding
- `oktava` — Purple/gold, Orbitron/Rajdhani, Oktava branding
- `bluetech` — Blue/cyan, Outfit/Inter, Bluetech branding
- `nguyen` — Gold/wood, Playfair/Inter, Nguyen Family branding

### 5. Unified Features
- Single login entry point with `?portal=` routing
- Shared task API integration (`/api/tasks/current`, `/api/tasks/log`)
- Shared practice log (`/api/practice`)
- Progress tracking (completion %, time logged)
- Daily work log with activity selector
- Responsive design
- Brand-aware theming via `data-theme` attribute

## Decisions
1. **Unified login over per-brand login:** Reduces duplication, easier maintenance
2. **Theme CSS variables:** Allows instant brand switching without JS logic changes
3. **Single app.html:** All portal features in one file, branded via JS at runtime
4. **Legacy portals preserved:** Old portals remain functional; new unified portal is opt-in via `?portal=` param
