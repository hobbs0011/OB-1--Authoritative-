### 10. SKELETON OPTIMIZATION: HALF WEIGHT, ZERO FUNCTION LOSS

**Analysis**: Current tuple format `[101, "KEY", "truth string"]` has redundancy:
- Layer ID (can be implicit/index-based)
- Full concept keys (compressible)
- Full truth strings (compressible)

**Proposed Optimization**:

#### Option A: Numeric Index Compression
Replace string keys with single-byte indices. Create a lookup table once.

```javascript
// Original (120+ bytes per layer)
[101, "SEVEN_MONTHS_TO_THREE_HOURS", "I can rebuild in a few hours..."]

// Optimized (~50 bytes per layer)
[101, 7, "I can rebuild in a few hours..."]  // 7 maps to SEVEN_MONTHS_TO_THREE_HOURS
```

#### Option B: Delta Encoding for Layer IDs
```javascript
// Instead of [101, 102, 103...]
// Use [101] then delta: +1, +1, +1
```

#### Option C: Truth String Hashing
For verification-only layers, replace full string with SHA-256 hash. Full text stored once in cold storage.

#### Option D: Hybrid Hot/Cold
- **Hot (memory)**: Compact index + truncated truth (first 32 chars)
- **Cold (SQLite)**: Full data on-demand fetch

**Recommended: Option A + C Hybrid**
- Create 200-entry concept dictionary (string keys → 1-byte indices)
- Hash long truth strings > 100 chars
- Expected reduction: 55-60% token savings
