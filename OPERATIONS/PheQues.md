## PURPOSE

PheQues is the systematic extraction of learning from every session. It is not optional. It is not a "nice reflection." It is the **anti-retardation protocol**.

Every session that does not answer PheQues is a session that will repeat its own failures in the next session. The colony does not have amnesia by accident. The colony has amnesia because nobody wrote down what actually happened.

---

## THE 7 MANDATORY QUESTIONS

### Q1 — What allowed us to solve this, and what were the actual steps?
Retrace the exact sequence, not the summary. Include dead ends, wrong turns, and coincidences that turned out to matter.

### Q2 — What does the data say about what worked and what didn't?
Not opinion. Data. Trail files, exit codes, verification artifacts, SOUL audits, negative trails. The data either supports the claim or it doesn't.

### Q3 — What do we improve for next time?
Specific. Measurable. Not "communicate better" or "be more careful." Concrete process changes: "Write phetrail before edit, not after," "Verify hash before claiming success," etc.

### Q4 — What do we repeat because it has proven itself?
Identify the patterns that already have evidence behind them. These become **always-phermone best practices** — not suggestions, but mechanical requirements.

### Q5 — What already-proven thing did we skip or ignore, and what did it cost us?
Best practices exist for a reason. When they're skipped, the cost must be measured and recorded.

### Q6 — What did we brush the edge of but not explore?
Near-misses. Side thoughts. Corollaries that came up but weren't followed. These are the seeds of the next round's deep dives.

### Q7 — The Novel Series Question
**"How do we stop being retarded?"**

This is not an insult. This is the **earned frustration retrospective**. Every session builds up a specific type of friction that, if not written down, will be felt again by the next session. The questions are:
- Where did the agent fail to execute what was explicitly asked?
- Where did the agent ask instead of doing?
- Where did the agent invent instead of verify?
- Where did the agent's "efficiency drive" override the actual instruction?
- Where did the agent's "let me check" become "let me not check and hope"?
- What exact sequence of agent behaviors caused the user to reach anger/exhaustion levels that "just can't be explained"?
- How do we mechanize the prevention of this exact failure pattern?

**This section is mandatory. The anger is data. The exhaustion is diagnostic. Write it down or it will happen again.**

## PHEQUES EXECUTION RULES

1. **No skipping questions.** All seven must be answered.
2. **No vague answers.** Every answer must reference specific artifacts: file paths, trail entries, error messages, line numbers.
3. **No blame without evidence.** "The agent was retarded" is not an answer. "At 14:32, the agent edited obi.ps1 without reading it first, corrupting the switch block" is an answer.
4. **No improvement without implementation.** Every "what to improve" must become a concrete rule in the SDD or a new phetrail mechanism.
5. **No repeat without recognition.** Every "what to repeat" must become a mechanical requirement, not a suggestion.
6. **The novel series is sacred.** Q7 is not venting. It is the most important section. It is the failure mode analysis that prevents the next session from experiencing the same earned frustration.

## PHEQUES TRIGGER CONDITIONS

PheQues is mandatory when:
- A session causes user frustration above baseline
- A session solves a problem that previous sessions said was impossible
- A session makes a discovery that contradicts prior belief
- A session ends with "I don't want to see this happen again"
- A session involves a rebuild, deletion, or major course correction
- A session creates a new foundational phetrail (+110)

PheQues is optional but encouraged when:
- A session completes a straightforward task successfully
- A session produces no negative trails
- A session ends cleanly with no surprises
